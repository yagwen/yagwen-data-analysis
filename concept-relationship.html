二、我的理解：三者怎么协作

用一句话串起来：Agent 是"人"，LLM 是它的"大脑"，上下文是大脑的"视野"，Skill 是它随身携带的"工作手册"。

1. 上下文的质量决定 Agent 的上限。Agent 再强，也只能基于上下文窗口里"看得见"的信息做决策。窗口里是清晰的指令和资料，它就表现专业；窗口里什么都没有，它就只能泛泛而谈。这解释了我以前的一个困惑：同一个 AI，有时像专家、有时像新手——差别往往不在模型，而在喂给它什么上下文。

2. Skill 是把"上下文"从临时变为持久的手段。上下文本身用完即清空，但 Skill 把"该放什么进上下文、按什么流程做"固化成文件，每次任务自动加载。它相当于对上下文的主动管理和复用——这和新闻传播里"把一次采访的素材整理成可检索的资料库"是一个道理。

3. 三者形成闭环。用户给目标 → Skill/记忆进入上下文 → LLM 基于上下文推理 → Agent 调用工具行动 → 结果反馈回上下文 → 做得好的方法沉淀成新 Skill。我在做本作业时亲历了这个闭环：AI 帮我生成的资料结构不错，我就把这套结构写成了 concept-learning Skill，下次直接复用。

三、逐对关系速查

关系一句话解释
Agent → 依赖 → LLM 上下文Agent 的每一步决策都只能基于当前上下文，上下文外的事它"看不见"
Skill → 注入 → LLM 上下文Skill 被触发时加载进上下文，把任务方法论带给模型
Agent → 调用/沉淀 → SkillAgent 执行时按 Skill 的流程走；执行中验证有效的新方法可写回 Skill，形成迭代
