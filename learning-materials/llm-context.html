大模型的上下文（LLM Context / 上下文窗口）

学习深度：入门 ｜ 生成工具：WorkBuddy + concept-learning-generator Skill ｜ 生成日期：2026-09-10

一句话定义：上下文（Context）是大语言模型在一次生成回答时能"看见"的全部信息——包括系统指令、历史对话、当前输入以及外部工具或检索注入的资料；它能装多少，由上下文窗口（Context Window）的长度决定。

一、概念通俗解释

先说一个生活化的类比：大模型就像一个隔着固定大小玻璃窗看房间的顾问——窗户就这么宽，窗内摆的东西它都看得一清二楚，留在窗外的它完全看不见。每次你提问，系统会把"系统设定 + 历史对话 + 你这句话 + 相关资料"一起塞进这扇窗户；模型只根据窗内的内容作答。

这个类比能直接解释两个日常困惑：

  • 为什么 AI 聊久了会"忘事"？——对话越来越长，早期内容被挤出窗口（滑出了玻璃窗），模型就真的看不见了，不是"记性差"，是"看不见"。
  • 为什么把要求写清楚、把资料直接贴给 AI 效果更好？——你在把关键信息主动放进它的窗户里，而且放到了显眼位置。模型不知道窗口外的一切，你没给的，它就只能靠"训练时背下的老知识"猜。

一句话总结：上下文是模型此刻的"全部世界"。理解了这一点，就理解了提示词工程、RAG、记忆机制这些热门概念的共同本质——它们都是在想办法把对的信息，在对的时机，放进这扇窗户。

二、核心机制与组成

1. 上下文里都装了什么？一次对话的上下文并非只有你说的话，而是多层信息叠加：

组成成分内容类比
系统提示词开发者在对话开始前注入的角色设定、规则（如"你是新闻写作助手"）顾问的"岗位说明书"
历史对话本轮会话中之前的所有问答会议纪要，越翻越厚
当前输入用户此刻的问题或指令你现在递进去的纸条
注入的资料检索到的文档片段（RAG）、工具返回结果、文件内容、记忆文件等临时塞进房间的参考资料

2. 核心运转机制：

输入 → 分词（Tokenization）→ 注意力计算（窗口内所有 token 互相"看见"）→ 逐个 token 生成回答
模型生成每个字时，都会同时"回看"窗口内的全部内容并分配注意力权重。所以窗口内的信息不仅决定模型"知道什么"，还决定它"此刻最关注什么"。

3. 三个关键机制要点：

要点说明
Token 是计量单位上下文按 token 计数，1 个汉字约 1~2 个 token，1 个英文单词约 1.3 个 token。主流模型的窗口从数万到上百万 token 不等（如 128K、200K、1M）
窗口 = 工作内存模型每次作答的依据就是窗口内的内容；窗口外的信息对它等于不存在。窗口接近上限时，最早的内容会被截断（"滑动窗口"）
位置影响注意力研究发现模型对开头和结尾的信息最敏感，超长输入中间的关键信息容易被忽略（"Lost in the Middle" 现象）——所以重要内容别埋在中间

三、实际应用场景案例

案例：企业知识库问答（RAG，检索增强生成）——上下文机制的典型应用

大模型自身的训练数据里没有某公司 2026 年的最新制度文件，直接问它"我们公司差旅报销标准是多少"必然瞎编。RAG 系统的做法是巧妙地"往窗口里塞东西"：

  1. 接收问题：用户提问"差旅报销标准是多少"；
  2. 检索：系统先在公司文档库里搜索，找出最相关的几个段落（比如《财务制度》第 3.2 节）；
  3. 注入上下文：把这些段落作为参考资料拼进上下文，一并交给模型；
  4. 生成：模型基于窗口内的真实资料作答，并注明出处。

这个案例说明：模型的回答质量，很大程度不取决于模型本身"多聪明"，而取决于窗口里有没有它需要的信息。日常使用中的"贴资料给 AI"“把要求写进 prompt”，本质上都是手动版的 RAG。

四、易混淆概念辨析 & 使用边界

易混概念关键区别
上下文 vs 训练数据（参数知识）训练数据是模型学习阶段读过、已"固化"进模型参数的海量资料（学完不再变）；上下文是使用阶段每次对话临时可见的窗口，用完即清空。前者是"背下来的知识"，后者是"桌上摊开的资料"
上下文窗口 vs 长期记忆窗口是临时的、单次会话的；长期记忆是把关键信息持久化到外部文件（如记忆文件、知识库），并在新会话开始时重新注入窗口——"记得"是被重新加载的，不是窗口一直没关
上下文 vs 提示词（Prompt）Prompt 通常指用户主动写的那部分输入；上下文是更大的概念，还包括系统提示、历史对话、工具返回结果等所有进入窗口的内容
上下文 vs 上下文学习（In-context Learning）上下文是"窗口里的信息"这个名词；上下文学习（ICL）是利用窗口内信息改变行为的能力——比如在 prompt 里给几个示例，模型立刻照着做，无需重新训练

使用边界与局限性（重要，避免误解）：

  • ❌ 窗口不是无限大：超过上限时早期内容会被截断，模型"失忆"发生在你不知不觉之间；使用长对话时要有意识控制信息量。
  • ❌ 窗口大 ≠ 用得好：研究表明即使窗口标称很大，模型对超长中间内容的利用率也会下降（Lost in the Middle），有效工作范围往往小于标称值。
  • ❌ 成本随 token 增长：API 计费通常按输入 + 输出的 token 数计算，把整本书塞进窗口既贵又慢，还稀释了模型的注意力——垃圾进，垃圾出。
  • ❌ 上下文结束即清空：关掉对话窗口里的内容就没了；跨会话的"记忆"必须依赖外部持久化机制，不要误以为模型"记住你"。
  • ✅ 正确用法：重要信息放开头或结尾；长对话定期总结前文；资料按需检索注入而非全量倾倒。

七、自测问题

1.【定义】用一句话说清"上下文窗口"是什么。

模型一次生成回答时能读取的最大信息量（以 token 计）；窗口内的内容对模型可见，窗口外的信息等于不存在。

2.【组成】一轮对话的上下文里除了你说的话，还可能有哪些内容？

系统提示词（角色与规则设定）、之前的历史对话、检索或工具注入的资料（RAG 文档片段、文件内容、记忆文件等）。

3.【机制】为什么重要信息最好放在 prompt 的开头或结尾？

模型对上下文开头和结尾的注意力最强，超长输入中间的信息容易被忽略（Lost in the Middle 现象），所以关键要求不要埋在长文本中间。

4.【辨析】AI 记得我上周和它聊的内容，是不是说明上下文窗口一直保留着？

不是。跨对话的"记得"通常是把关键信息持久化到外部文件/数据库，并在新对话开始时重新注入上下文实现的；窗口本身每次会话都是新的，会话结束即清空。

5.【辨析】模型的训练数据和上下文有什么区别？

训练数据是学习阶段读入并固化到模型参数里的海量资料，学完固定，属于"背下来的知识"；上下文是使用阶段每次对话临时可见的窗口内容，用完即清空，属于"桌上摊开的资料"。

6.【思考】把一份 500 页的 PDF 全部塞进上下文让 AI 总结，可能有哪些问题？

（1）可能超出窗口上限导致内容被截断；（2）即使塞得下，中间部分信息利用率低（Lost in the Middle），总结质量下降；（3）token 费用高、响应慢；（4）无关内容稀释注意力。更好的做法是分章节处理或按需检索相关片段。

7.【思考】RAG 和"把资料直接贴给 AI"在机制上是同一件事吗？

本质上是同一件事——都是把资料放进上下文窗口让模型"看得见"。区别只在自动化程度：手动贴资料是人来决定放什么；RAG 是由检索系统自动找出最相关的片段再注入。二者共同印证：模型回答质量很大程度取决于窗口内有什么。
