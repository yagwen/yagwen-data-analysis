Agent（智能体）

学习深度：入门 ｜ 生成工具：WorkBuddy + concept-learning-generator Skill ｜ 生成日期：2026-09-10

一句话定义：Agent（智能体）是一个以"目标"为单位工作的 AI 系统——它能自主理解任务、规划步骤、调用外部工具、执行行动，并根据执行结果的反馈不断调整，直到完成目标。

一、概念通俗解释

先说一个生活化的类比：普通的 AI 聊天就像问询台的服务员——你问一句，它答一句，你不问它就闲着；而 Agent 更像你雇来的一位助理——你只说"帮我把这件事办成"，至于分几步做、中间要查什么资料、用哪些工具、出了问题怎么补救，都由它自己安排，只在关键节点回来向你确认。

展开来讲，一个 AI 系统要被称为 Agent，通常要满足三个特征：

  • 自主性（Autonomy）：拿到目标后自己决定"下一步做什么"，而不是每一步都等人下指令；
  • 工具使用（Tool Use）：能调用自身之外的工具——搜索引擎、代码执行器、文件系统、API——来弥补"只会说话"的短板；
  • 闭环反馈（Feedback Loop）：做完一步会观察结果，成功就继续，失败就换方法，而不是一口气把错误执行到底。

在 AI 领域语境下，今天大家说的 Agent 通常特指 LLM-based Agent（基于大语言模型的智能体）：用大模型当"大脑"，再配上规划、记忆和工具，让 AI 从"会说"进化到"会做"。

二、核心机制与组成

学界和业界对 Agent 的组成有不同的拆法，但主流框架大同小异。以 Lilian Weng 的经典框架为例，一个 LLM Agent 由四大模块组成：

模块作用通俗类比
规划（Planning）把大目标拆解为可执行的小步骤（任务分解）；执行中反思已有结果、发现偏差时重新规划（反思与重规划，如 ReAct、Reflexion 等方法）助理先列工作计划，做到一半发现走不通就改计划
记忆（Memory）短期记忆：保存当前任务的上下文（受模型上下文窗口限制）；长期记忆：把经验、资料写入外部存储（向量数据库等），跨任务可复用便签纸记眼前的事，笔记本记长久的经验
工具使用（Tool Use）调用搜索、计算器、代码执行器、各类 API 等，让模型能获取实时信息、进行精确计算、操作真实系统助理不会心算就按计算器，不知道就上网查
行动（Action）真正执行操作并产生实际效果，是 Agent 区别于"只出主意"的关键真的把事办了，而不是只给建议

这四个模块通过一个核心的运转机制串起来，即 Agent Loop（智能体循环）：

思考（Thought）→ 行动（Action）→ 观察（Observation）→ 再思考 → ……（循环直到目标达成）
每轮循环中，LLM 先思考当前该做什么，然后调用一个工具执行，工具返回的结果（观察）再喂回给 LLM 判断下一步。这个"边想边做边看结果"的机制就是 ReAct 范式的核心，也是所有 Agent 框架的底层逻辑。

复杂度阶梯（Anthropic 的观点）：并非所有多步 AI 应用都需要完整的 Agent。Anthropic 在《Building Effective Agents》中提出一个从简单到复杂的谱系：

层级谁决定步骤说明
单次 LLM 调用用户一问一答，最简单
Workflow（工作流）开发者预先编排把多个 LLM 调用按固定路径串起来（如先生成再检查）
Agent（智能体）模型自主决定模型自己决定调用什么工具、执行多少步，直到完成任务

Anthropic 的建议是：能用简单方案就别上 Agent——只有在任务步骤无法预先确定、需要模型灵活决策时，Agent 才是正确选择。

三、实际应用场景案例

案例：编程 Agent 自主修复 Bug（真实落地场景）

以当前已商用的 AI 编程助手为例，用户只输入一个目标："这个项目的测试挂了，帮我修好。"接下来 Agent 自主完成一整串工作：

  1. 规划：先运行测试，读报错信息，定位可疑文件；
  2. 工具使用：调用代码执行器跑测试、用文件读取工具查看相关源码；
  3. 观察反馈：发现第一个修改没有通过测试，于是回退改动、重新分析原因；
  4. 行动：最终提交正确的修复代码，并附上修改说明。

整个过程中用户没有再输入任何指令——这就是典型的"以目标为单位、自主多步执行"的 Agent 行为。其他已落地的场景还包括：电商客服 Agent（查订单、办退换）、数据分析 Agent（自己写代码、跑分析、出图表）、办公自动化 Agent（读邮件、订会议、写纪要）等。

四、易混淆概念辨析 & 使用边界

易混概念关键区别
Agent vs 聊天机器人聊天机器人以一轮问答为单位被动响应，用户不推进它就不动；Agent 以一个目标为单位主动推进，可连续执行多步操作
Agent vs 大语言模型（LLM）LLM 只是 Agent 的"大脑"（负责思考和决策的组件）；Agent = LLM + 规划 + 记忆 + 工具 + 执行。LLM 只能"说"，Agent 能"做"
Agent vs Workflow（工作流）Workflow 的步骤由开发者预先编排，路径固定；Agent 的步骤由模型运行时自主决定，路径灵活。这是 Anthropic 强调的核心分界线
Agent vs RPA / 传统自动化脚本RPA 按写死的规则执行，遇到规则外的情况就失败；Agent 遇到意外情况能理解、适应、换方案

使用边界与局限性（重要，避免神化）：

  • ❌ 错误会被放大：LLM 的幻觉一旦进入行动环节，Agent 可能"自信地执行一个错误决定"。步骤越多，累积出错概率越高，长任务的可靠性会明显下降。
  • ❌ 成本高、速度慢：Agent 完成任务需要多轮 LLM 调用，比单次问答贵得多、慢得多。简单、路径固定的任务用 Workflow 或脚本更划算。
  • ❌ 需要权限与安全约束：Agent 能"做事"也就意味着能"做错事"或"被滥用"，真实系统必须配置权限边界、审批环节和沙箱环境，不能放任其无监督地操作关键系统。
  • ❌ 依赖工具质量：Agent 的能力上限受制于它能调用什么工具、工具返回的数据质量如何——没有合适的工具，再聪明的规划也无从落地。
  • ✅ 适用的判断标准：任务步骤无法提前写死、需要灵活决策、且允许"试错-修正"的场景，才值得用 Agent。

七、自测问题

1.【定义】Agent 区别于普通聊天 AI 的三个关键特征是什么？

自主性（自己决定下一步）、工具使用（调用外部工具扩展能力）、闭环反馈（观察执行结果并调整行动）。

2.【机制】Agent 的四大组成模块是什么？各自解决什么问题？

规划（拆解任务、反思重规划）、记忆（短期上下文 + 长期经验存储）、工具使用（搜索/计算/执行等外部能力）、行动（真正执行操作产生效果）。

3.【机制】Agent Loop 的三个基本环节是什么？为什么"观察"环节不可缺少？

思考→行动→观察。"观察"把工具执行的结果反馈给模型，模型据此判断成功还是失败、决定下一步——没有它，Agent 就无法修正错误，只会把错误执行到底。

4.【辨析】Workflow 和 Agent 的本质区别是什么？各适合什么场景？

Workflow 的调用路径由开发者预先编排，固定可控，适合步骤明确的任务；Agent 的步骤由模型运行时自主决定，灵活但成本高、不确定性大，适合无法提前写死步骤、需要动态决策的任务。

5.【辨析】"LLM 就是 Agent"这句话对吗？请说明两者关系。

不对。LLM 只是 Agent 的"大脑"组件，负责思考和决策；Agent 是完整系统 = LLM + 规划 + 记忆 + 工具 + 执行。只有 LLM 而没有其余部分，就只能对话，不能自主做事。

6.【思考】如果你的需求是"每天固定抓取三个网站的新闻标题并存成表格"，你会用 Agent 还是普通脚本？为什么？

普通脚本（或定时任务 + Workflow）。因为步骤完全固定、可提前写死，不需要模型动态决策——按 Anthropic 的原则，这种场景用 Agent 是浪费成本且引入不必要的出错风险。（言之成理即可）

7.【思考】为什么说 Agent 的可靠性会随任务步骤增多而下降？请结合幻觉和误差累积解释。

LLM 每一步都有一定概率出错（幻觉、误判）。Agent 多步执行时，若某步的错误结果进入后续循环，错误会被放大和累积；步骤越多，全程无错的联合概率越低，因此长任务可靠性明显下降，需要检查点、人工审批等机制兜底。
